Ventanas · Motivación
¿Por qué necesitamos ventanas?
La ventana existe por la STFT — no por la DFT

Cuando hacés una sola DFT de una señal completa, no necesitás ventana — estás analizando todo el bloque entero.

El problema aparece cuando querés analizar pedazos de una señal. Cuando cortás un pedazo, los bordes quedan abruptos — como si cortaras una canción en un punto arbitrario. Esa discontinuidad genera frecuencias falsas (leakage).

La ventana suaviza esos bordes antes de hacer la FFT a cada pedazo.

El flujo real del análisis espectral:

1. Cortás un pedazo de señal
↓
2. Le aplicás la ventana (suavizás los bordes)
↓
3. Le hacés FFT a ese pedazo ventaneado
↓
4. Avanzás y repetís → eso es la STFT

Sin ventana, cada trozo que cortás tiene leakage horrible y el espectrograma queda inservible.

Ventanas · Concepto
¿Qué es una ventana?
Un array de valores entre 0 y 1 que multiplicás sample a sample
Es un vector de N números
Cada valor está entre 0.0 y 1.0. En el centro valen ~1, en los bordes bajan a ~0.
Se aplica multiplicando
Cada sample de tu señal se multiplica por el valor correspondiente de la ventana: señal[n] × ventana[n]
Resultado
Los samples del centro quedan casi iguales (×1). Los de los bordes se atenúan hasta cero (×0). Los cortes abruptos desaparecen.
aplicar ventana C++ 
for (int n = 0; n < N; n++)
    resultado[n] = señal[n] * ventana[n];
Ventanas · El problema
¿Qué pasa cuando cortás un pedazo?
A veces tenés suerte, casi siempre no

No podés depender de la suerte. Una señal real rara vez empieza y termina en cero. El corte casi siempre cae en un valor arbitrario.

La FFT repite el pedazo
La FFT trata tu pedazo como si fuera periódico — asume que se repite para siempre. Si el final no conecta con el principio, hay un salto.
La ventana fuerza los bordes a cero
No importa dónde caigas: la ventana garantiza que los extremos siempre estén en cero. Sin salto, sin discontinuidad.

Ese salto genera frecuencias que no existen en tu señal. A eso le llamamos spectral leakage — lo vemos en el próximo slide.

El problema
Spectral leakage (fuga espectral)
Por qué la FFT "derrama" energía a frecuencias vecinas

La FFT asume que tu señal es periódica — que el último sample conecta perfectamente con el primero. Si no conecta, hay una discontinuidad invisible que genera frecuencias falsas.

Sin ventana — discontinuidad en los bordes
El espectro de un tono puro no es un pico limpio — la energía se "derrama" a los bins vecinos. El efecto se llama spectral leakage.
Con ventana — bordes suavizados a cero
La ventana multiplica la señal por una curva que lleva los extremos a cero. La discontinuidad desaparece — el pico queda más limpio.
Ejemplo guiado
Las tres ventanas
Hamming, Hann, Blackman — distintos trade-offs entre resolución y supresión
ventanas.cpp C++ 
for (int n = 0; n < N; n++) {
    float t = (float)n / (N - 1);   // t va de 0.0 a 1.0

    w_hamming[n]  = 0.54f - 0.46f * cos(2 * M_PI * t);
    w_hann[n]     = 0.5f  - 0.5f  * cos(2 * M_PI * t);
    w_blackman[n] = 0.42f - 0.5f * cos(2*M_PI*t)
                           + 0.08f* cos(4*M_PI*t);

    // aplicar: multiplicar sample a sample
    signal_ventaneada[n] = signal[n] * w_hann[n];
}
Hamming La más usada en audio. Buen balance — lóbulo lateral bajo, resolución aceptable.
Hann Muy similar a Hamming. Más usada en análisis espectral general. Cae exactamente a cero en los bordes.
Blackman Lóbulos laterales muy bajos. Sacrifica resolución. Buena para detectar señales débiles cerca de señales fuertes.
Ventanas · Herramienta
Zero-padding
Rellenar con ceros para que la FFT funcione mejor
La FFT necesita potencias de 2
Si tu ventana tiene 63 muestras, no podés hacer FFT de 63. Necesitás 64, 128, 256, 512... Rellenás con ceros hasta llegar.
Más puntos en el gráfico
FFT de 63 puntos → 31 bins (gráfico tosco). FFT de 512 puntos → 256 bins (gráfico suave). No agrega información, solo detalle visual.
Es como hacer zoom en una foto
Ves más píxeles pero no más detalle. La resolución real sigue siendo la de tu ventana original.
Desarrollo · Rectangular
¿Qué es una ventana Rectangular?
Sin ventana — todos los valores = 1
Es simplemente 1.0 en todos lados
No multiplicás nada — usás la señal tal cual está.
La más simple: sin procesamiento
w[n] = 1.0 para todo n
Mejor resolución frecuencial
El lóbulo principal es el más angosto — dos tonos cercanos se ven claramente separados.
Peor leakage
Los lóbulos laterales son los más altos — si hay una señal fuerte, sus artefactos contaminan el espectro.
Matemáticas · Rectangular
La fórmula de Rectangular
La más trivial
w[n] Fórmula 
w[n] = 1.0  // para todo n

O sea:

Sin cambios
La señal entra sin modificarse. w[n] = 1 significa "multiplica por 1" = no hace nada.
Cortes abruptos
Los bordes de tu trozo de señal están a su valor máximo (no suavizados).
FFT ve saltos
La discontinuidad en los bordes genera artefactos espectrales — los lóbulos laterales.
Ejercicio · Rectangular
¿Qué pasa si le hacemos FFT a esta ventana?
La ventana tiene su propio espectro — y eso explica todo

¿Por qué hacemos esto? Porque cuando ventaneás una sinusoide, lo que ves en el espectro no es solo tu señal — es la forma del espectro de la ventana centrada en la frecuencia de tu señal. Si la ventana tiene picos laterales altos, esos picos aparecen como frecuencias falsas alrededor de cada nota que analices. Por eso queremos ver la forma de la ventana antes de usarla.

// 1. Generar la ventana (63 muestras, todas 1.0)
auto ventana = rectangular(63);

// 2. Meter en un buffer grande (zero-padding)
//    63 valores + 449 ceros = 512 puntos

// 3. Calcular FFT del buffer
auto espectro = fft(buffer);

// 4. Convertir a dB y graficar
//    → vas a ver el lóbulo principal
//       y los lóbulos laterales
Lóbulo principal = el pico central
Cuántos bins ocupa. Más angosto = mejor resolución (distinguís frecuencias cercanas).
Lóbulos laterales = los picos a los costados
Qué tan altos son (en dB). Más altos = más leakage = más frecuencias falsas.

Rectangular:

Lóbulo principal: 2 bins (angosto, buena resolución)

Lóbulo lateral: -13 dB (alto, mucho leakage)

Forma · Rectangular
Cómo se ve Rectangular
Una línea plana
Borde izquierdo (n=0)
w[0] = 1.0 (sin atenuación)
Centro (n=N/2)
w[N/2] = 1.0 (igual que en los bordes)
Borde derecho (n=N-1)
w[N-1] = 1.0 (sin atenuación)
El problema
Los valores no bajan en los bordes — hay discontinuidades abruptas cuando cortas la señal.
Análisis · Rectangular
Rectangular vs otras ventanas
El extremo opuesto: máxima resolución, mínima supresión

Rectangular tiene:

Lóbulo principal MÁS ANGOSTO
Mejor resolución que cualquier otra ventana — dos tonos muy cercanos se ven claramente como dos picos.
Lóbulos laterales MÁS ALTOS
El peor leakage de todas las ventanas — los artefactos espectrales dominan.

En la práctica:

Casi nunca se usa
El leakage es tan alto que hace el análisis espectral poco útil en la mayoría de casos.
Excepto en casos especiales
Si tenés una señal periódica perfecta (número entero de ciclos en N), Rectangular funciona bien.

Desarrollo · Hamming
¿Qué es una ventana Hamming?
Una función matemática que multiplica tu señal
Es una lista de números entre 0 y 1
Uno por cada muestra. Baja en los bordes, pico en el centro.
Se multiplica elemento a elemento con tu señal
señal_ventaneada[n] = señal[n] × ventana[n]
Suaviza los bordes a cero
Evita que FFT vea "saltos abruptos" que crean artefactos espectrales.
Los coeficientes 0.54 y 0.46 son específicos de Hamming
Otros valores crean otras ventanas (Hann, Blackman, etc.)
Matemáticas · Hamming
La fórmula de Hamming
Cómo se genera la ventana
w[n] Fórmula 
w[n] = 0.54 - 0.46 * cos(2π * n / (N-1))

Cómo se interpreta:

n
Índice de la muestra — va de 0 a N-1
N
Tamaño total de la ventana (ej: 1024 muestras)
cos(2π * n / (N-1))
Oscila entre -1 y 1 conforme n va de 0 a N-1
0.54 - 0.46 * (...)
Desplaza y escala para que valga entre ~0.08 y 1.0
Forma · Hamming
Cómo se ve Hamming
Gráfico y valores clave
Borde izquierdo (n=0)
w[0] = 0.54 - 0.46 = 0.08
Centro (n=N/2)
w[N/2] ≈ 1.0
Borde derecho (n=N-1)
w[N-1] = 0.54 - 0.46 = 0.08
Aplicación · Hamming
Cómo se multiplica con la señal
Multiplicación elemento a elemento
pseudocódigo Algoritmo 
Para cada muestra n (0 hasta N-1):
    valor_ventana = 0.54 - 0.46 × cos(2π × n / (N-1))
    resultado[n] = señal[n] × valor_ventana
implementación C++ 
for (int n = 0; n < N; n++) {
    float ventana = 0.54f - 0.46f * cos(2.0f * M_PI * n / (N - 1));
    resultado[n] = signal[n] * ventana;
}

O solo multiplicar con vector precomputado:

resultado[n] C++ 
for (int n = 0; n < N; n++)
    resultado[n] = signal[n] * ventana[n];

Ejemplo visual:

señal: [ 0.5, 0.7, 0.9, 0.8, 0.2]
ventana: [ 0.0, 0.5, 1.0, 0.5, 0.0]
× ─────────────────────────────
resultado: [ 0.0, 0.35, 0.9, 0.4, 0.0] ← atenuada en bordes

Qué pasa:

Bordes: ventana vale ~0
Cualquier valor × 0 = 0
Centro: ventana vale ~1
Cualquier valor × 1 = mismo valor
Resultado: sin saltos abruptos
FFT ve una señal que empieza y termina naturalmente en cero
Resumen · Hamming
Hamming en audio
Por qué es la más usada
La más usada en audio digital
Buen balance entre supresión de lóbulos laterales y resolución espectral.
Lóbulos laterales moderados
Mejor que Rectangular, no tan buena como Blackman.
Resolución frecuencial aceptable
Dos tonos cercanos se ven como dos picos separados.
Recomendación
Úsala como primera opción en plugins de análisis. Si necesitas más supresión, cambiá a Blackman. Si necesitas más resolución, probá Hann.
Desarrollo · Hann
¿Qué es una ventana Hann?
Similar a Hamming, con una diferencia clave en los bordes
Muy similar a Hamming
Misma forma de campana, coeficientes ligeramente diferentes.
Cae exactamente a cero en los bordes
Hamming vale 0.08 en los bordes; Hann vale exactamente 0.
Mejor para overlap en STFT
Cuando solapas ventanas Hann, se suman a 1 en toda la señal — sin gaps ni picos.
Estándar en análisis espectral
Es la que usan los analizadores de espectro de los DAWs (JUCE la usa por defecto).
Matemáticas · Hann
La fórmula de Hann
Cómo se genera la ventana
w[n] Fórmula 
w[n] = 0.5 - 0.5 * cos(2π * n / (N-1))

Comparación con Hamming:

Hamming: 0.54 - 0.46 * cos(...)
Coeficientes asimétricos → bordes no llegan a cero
Hann: 0.5 - 0.5 * cos(...)
Coeficientes simétricos → bordes exactamente cero
Resultado
Hann es más "pura" matemáticamente — mejor para STFT con overlap.
Forma · Hann
Cómo se ve Hann
Bordes a cero, centro al uno
Borde izquierdo (n=0)
w[0] = 0.5 - 0.5 = 0.0 ✓ exactamente cero
Centro (n=N/2)
w[N/2] = 1.0
Borde derecho (n=N-1)
w[N-1] = 0.5 - 0.5 = 0.0 ✓ exactamente cero
Diferencia vs Hamming
Ligeramente más pronunciada en los bordes (toca cero, no queda en 0.08)
Aplicación · Hann
Por qué Hann es mejor para STFT
Cuando solapas ventanas, se suman correctamente

Con Hann (bordes = 0):

ventana 1: [0.0, 0.5, 1.0, 0.5, 0.0, ...]
ventana 2: [0.0, 0.5, 1.0, 0.5, 0.0, ...]
suma: [0.0, 0.5, 1.0, 1.0, 1.0, 0.5, 0.0] ← uniforme, sin gaps

Con Hamming (bordes = 0.08):

ventana 1: [0.08, 0.5, 1.0, 0.5, 0.08, ...]
ventana 2: [0.08, 0.5, 1.0, 0.5, 0.08, ...]
suma: [0.08, 0.5, 1.08, 1.08, 0.58, 0.08] ← desigual, peaks
Conclusión
Para STFT con overlap, Hann es la opción correcta. Hamming funciona pero deja artefactos al solapar.
Resumen · Hann
Hann en práctica
Cuándo usarla
Primera opción para STFT
Si vas a hacer análisis espectral con ventanas deslizantes (solapadas), usa Hann.
Estándar en DAWs
JUCE, Reaper, y la mayoría de plugins usan Hann internamente.
Bordes exactamente cero
Matemáticamente más pura que Hamming.

Desarrollo · Blackman
¿Qué es una ventana Blackman?
La más sofisticada: dos cosenos
Dos términos coseno (no uno)
Usa 2πt y 4πt — más oscilaciones = forma más controlada.
Supresión de lóbulos más agresiva
Los artefactos espectrales son mucho más bajos que Hamming.
Lóbulo principal más ancho
Para lograr supresión, sacrifica resolución — dos tonos cercanos pueden verse como uno.
Ideal para detectar señales débiles
Cuando hay una señal fuerte y otra débil cerca, Blackman evita que la fuerte "oculte" la débil.
Matemáticas · Blackman
La fórmula de Blackman
Dos términos coseno para máxima supresión
w[n] Fórmula 
w[n] = 0.42 - 0.5 * cos(2π*n/(N-1))
         + 0.08 * cos(4π*n/(N-1))

Desglose:

0.42 (offset)
Línea base que desplaza la curva hacia arriba.
- 0.5 * cos(2πt)
Primer coseno — forma principal de la campana (como Hamming/Hann).
+ 0.08 * cos(4πt)
Segundo coseno (el doble de frecuencia) — refina la forma para mejor supresión.
Resultado
Más términos = más control sobre los lóbulos laterales.
Forma · Blackman
Cómo se ve Blackman
Campana muy suave y ancha
Mucho más ancha
Comparada con Hamming/Hann, el lóbulo principal es notablemente más ancho.
Muy suave
Sin quiebres ni vértices — la segunda oscilación de coseno la suaviza aún más.
Bordes casi cero
Muy cercanos a 0, aunque no exactamente (como Hamming).
Comparación
Hamming (pico fino) → Blackman (pico ancho). Trade-off extremo.
Análisis · Blackman
Cuándo elegir Blackman
El extremo de la supresión

Mejor para:

Detectar señales débiles cerca de fuertes
Los lóbulos laterales bajos evitan que la fuerte "enmascare" la débil.
Análisis de ruido
Si hay mucho ruido o artefactos, Blackman los suprime mejor.
NO para resolver tonos cercanos
El lóbulo ancho puede fusionar dos frecuencias que Hamming vería separadas.

Ejemplo:

Señal: 440 Hz + 480 Hz (débil, 10x menos energía)

Con Hamming: Ves dos picos separados ✓
Con Blackman: Ves uno solo (la débil enmascarada) ✗

STFT
Short-Time Fourier Transform
Analizando cómo evoluciona el espectro en el tiempo
DFT = una fotografía global
Te dice qué frecuencias hay, pero NO cuándo cambian.
STFT = muchas fotografías rápidas
Aplicas DFT en ventanas móviles. Ves el espectro evolucionando.
Resultado: espectrograma
Matriz tiempo × frecuencia. Lo que ves en Ableton, Reaper, analizadores.
STFT · Parámetros
frame_size y hop_size
El trade-off fundamental: tiempo vs frecuencia
Frame size GRANDE (2048, 4096)
✓ Resolución de frecuencia
Bins estrechos (~21 Hz por bin a 44100 Hz, window=2048).
✗ Resolución de tiempo
Menos actualizaciones (23 ms per frame).

Uso: análisis de tono, voces sostenidas.

Frame size PEQUEÑO (256, 512)
✗ Resolución de frecuencia
Bins anchos (~172 Hz por bin a 44100 Hz, window=256).
✓ Resolución de tiempo
Muchas actualizaciones (~6 ms per frame).

Uso: música rápida, drums, transitorios.

Matriz tiempo × frecuencia, intensidad como color
Línea horizontal = frecuencia constante
Una nota sostenida, un tono puro.
Línea que sube/baja = glissando
Cambio de frecuencia en el tiempo (bend, portamento).
Zona colorida = transitorio
Energía impulsiva (ataque de instrumento, ruido).
Silencio = oscuro
Bajo nivel de energía.
STFT · Código
Implementación en C++
El núcleo del análisis tiempo-frecuencia
pseudocódigo STFT Algoritmo 
Para cada posición start (de 0 al fin, paso hopSize):
    1. Extraer frame de tamaño windowSize
    frame = señal[start : start + windowSize]
    
    2. Aplicar ventana (Hann, Hamming, etc)
    frame = frame × ventana
    
    3. Calcular FFT
    espectro = FFT(frame)
    
    4. Guardar magnitudes (solo hasta Nyquist)
    espectrograma[tiempo] = |espectro[0 : windowSize/2]|
    tiempo += 1
implementación C++ 
for (int start = 0; start + windowSize <= signal.size(); start += hopSize) {
    // extraer frame y aplicar ventana
    vector<complex<float>> frame(windowSize);
    for (int i = 0; i < windowSize; i++)
        frame[i] = signal[start + i] * ventana[i];  // windowed

    // FFT
    auto espectro = fft(frame);

    // guardar magnitudes
    for (int k = 0; k < windowSize/2; k++)
        espectrograma[tiempo][k] = abs(espectro[k]);
}

Nota: Se guarda solo hasta Nyquist (windowSize/2) porque la segunda mitad es espejo.
